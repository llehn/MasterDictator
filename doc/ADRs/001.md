# Line endings are decided by .gitattributes, never by hand

## Decision

`.gitattributes` decides line endings: everything is stored and checked out with Unix endings,
except batch files, which Windows will not run without Windows endings.

Line endings are never fixed by hand. Not with a script, not as a one-off conversion, not for a
single file.

## Rationale

Fixing endings by hand means a tool wrote the file wrongly and the symptom is being swept up while
the cause stays. It returns on the next file, and the one after that.

Before `.gitattributes` existed the repository held a mixture of both kinds, and every whole-file
rewrite produced a diff in which every line had changed. A diff like that hides the change inside
it and cannot be reviewed.

## Consequences

Line endings appearing in a diff mean one of two things: a broken tool, or a hole in
`.gitattributes`. Both are reported as such and fixed at the source.

Neither is tidied away quietly, and neither is treated as a normal part of doing the work.
